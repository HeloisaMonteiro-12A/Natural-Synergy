Por dentro do protótipo

Componentes, arquitetura, ligações elétricas e a lógica de detecção que fazem o Natural Synergy funcionar.

Hardware

Componentes utilizados

ESP32

Microcontrolador dual-core com Wi-Fi e Bluetooth integrados. É o “cérebro” do sistema: lê os sensores, processa os dados e envia os alertas pela internet.

Sensor de batimentos

Sensor óptico (ex.: MAX30102 ou Pulse Sensor) que mede a frequência cardíaca. Uma elevação brusca de BPM (taquicardia) é comum durante crises.

Sensor de movimento

Acelerômetro e giroscópio (ex.: MPU6050) que identifica movimentos rítmicos e intensos, característicos de crises tônico-clônicas.

Buzzer

Emite um sinal sonoro para alertar pessoas próximas assim que uma possível crise é detectada.

Botão

Permite cancelar falsos alarmes (toque rápido) ou enviar um pedido de ajuda manual (pressionar por 3 segundos).

LED

Indicador visual do estado: verde para monitoramento normal e vermelho para alerta.

Protoboard

Placa de ensaio fixada sobre o manguito, onde o ESP32 e os demais componentes são encaixados e ligados sem solda.

Manguito

Peça de tecido que cobre todo o antebraço e serve de base para a protoboard, mantendo os sensores firmes junto à pele.

Formato · Modelo 3D

Um manguito que veste o antebraço

O protótipo é um manguito preto que cobre todo o antebraço, do punho até perto do cotovelo. Em cima dele fica a protoboard com o ESP32, o buzzer, o LED e o botão.

Os sensores ficam presos ao manguito e ligados à protoboard por jumpers: o de movimento perto do cotovelo e o de batimentos na parte de baixo do punho, em contato com a pele.

Arraste para girar, use a roda do mouse (ou dois dedos) para aproximar e clique em uma peça para ver o que ela faz.

    Arquitetura

    Como os dados circulam

    Os sensores enviam leituras ao ESP32, que decide localmente se há risco. Os dados e alertas seguem pela internet até o painel web e os contatos.

    Algoritmo

    Lógica de detecção

    O protótipo usa regras de limite combinadas, o que reduz falsos alarmes: um único sinal alterado sozinho não dispara o alerta.

    • Batimentos: BPM acima do limite configurado (ex.: 120) ou aumento súbito de mais de 30% em relação à média de repouso.
    • Movimento: aceleração com alta variação e padrão repetitivo durante vários segundos seguidos.
    • Confirmação: as duas condições precisam ocorrer juntas por pelo menos 10 segundos.
    • Cancelamento: após detectar, o sistema aguarda 10 s para o usuário cancelar pelo botão.

    Trecho do código (Arduino / C++)

    Laço principal simplificado mostrando leitura, detecção, aviso local e envio do alerta.

    #define PINO_BUZZER 25
#define PINO_LED    26
#define PINO_BOTAO  27

const int   LIMITE_BPM       = 120;
const float LIMITE_MOVIMENTO = 2.5;    // variação em g
const int   TEMPO_CONFIRMA   = 10000;  // ms
const int   TEMPO_CANCELAR   = 10000;  // ms

unsigned long inicioSuspeita = 0;

void loop() {
  int   bpm       = lerBatimentos();
  float movimento = lerVariacaoAceleracao();
  enviarLeituraParaPainel(bpm, movimento);

  // Pedido de ajuda manual: botão pressionado por 3 s
  if (botaoPressionadoPor(3000)) {
    enviarAlerta("Pedido de ajuda manual (SOS)");
  }

  bool suspeita = bpm > LIMITE_BPM && movimento > LIMITE_MOVIMENTO;

  if (!suspeita) { inicioSuspeita = 0; return; }
  if (inicioSuspeita == 0) inicioSuspeita = millis();

  if (millis() - inicioSuspeita >= TEMPO_CONFIRMA) {
    acionarAvisoLocal();                 // LED vermelho + buzzer
    if (!usuarioCancelou(TEMPO_CANCELAR)) {
      enviarAlerta("Possível crise detectada");  // contato + usuário
    }
    desligarAvisoLocal();
    inicioSuspeita = 0;
  }
}
